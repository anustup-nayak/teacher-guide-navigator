# Content model (v2)

Phase 2 of the [content architecture plan](CONTENT_ARCHITECTURE_PLAN.md). Draft, 31 October 2026;
awaiting the curriculum-design review gate ✋. It is written from the two
[program profiles](../curricula/up-hindi-2026/model/PROGRAM_PROFILE.md) ([Math](../curricula/up-math-2026/model/PROGRAM_PROFILE.md)).

- Schemas: [`schemas/content-model/`](../schemas/content-model/) (one per model file, plus `common`).
- Vocabularies: [`vocabularies.json`](../schemas/content-model/vocabularies.json). Schema enums must
  equal them (`tests/content-model.test.mjs`).
- Validator: `node scripts/content/schema.mjs <schema> <file.json>…` (no dependencies).
- Worked examples: [`docs/content-model/examples/`](content-model/examples/), regenerated by
  `node scripts/content/build_examples.mjs` (needs `python3 scripts/content/extract_matter.py` first).

## 1. Files per pack (`curricula/<pack>/model/`)

| File | Schema | Holds |
|---|---|---|
| `program.json` | program | edition, documents, week kinds, weekly cycle (day → purpose), periods (number, minutes, role, focus, materials) |
| `outcomes.json` | outcomes | strands → outcomes → sub-outcomes; Math weekly objectives |
| `sequence.json` | sequence | units (week blocks) with objectives, outcomes, textbook lessons, page ranges |
| `routines.json` | routines | the activity library: what / why / how / watch-outs, period, minutes, materials |
| `materials.json` | materials | textbooks, workbook parts, charts, posters, big books, kits, grids |
| `assessments.json` | assessments | checking understanding, weekly ‘मैंने सीख लिया’, periodic, oral-language, fluency; groups A/B |
| `guide/<grade>.json` | guide | program-guide sections → passages (source text, summary, classroom actions) |
| `lessons/<grade>.json` | lesson | day → periods → steps, with links |
| `sections.json`, `pagemap.json` | sections | Phase 1 section map and page coverage (exists) |

## 2. Identifiers

IDs are stable once published. Never rename one; deprecate and add a new one.

| Entity | Rule | Examples |
|---|---|---|
| Lesson | unchanged v1 id | `g1-hindi-w09-d02`, `g1-math-w09-d01` |
| Step | unchanged v1 phase id, unique within its lesson | `p2-1`, `we-do` |
| Outcome | printed code when there is one, else `g<grade>-<strand>-<n>` from the printed numbering | `H104.2`, `M101.1`, `g1-oral-language-1` |
| Sub-outcome | printed code; `parent` = the code before the dot | `H104.2` → `H104` |
| Weekly objective (Math) | `g<grade>-w<ww>-o<n>`, n = order in the annual table | `g1-w09-o1` |
| Unit | `g<grade>-u-w<from>[-<to>]` from the annual objectives table | `g1-u-w09-12` |
| Routine | `<subject prefix>-<ascii slug>` | `hi-picture-chart`, `math-grr` |
| Material | ascii slug; grade in the slug when grade-specific | `textbook-sarangi-1`, `workbook-g1-part-2` |
| Guide section | `g<grade>/<section id from sections.json>` | `g1/weekly-cycle` |
| Passage | `<section>/<n>` | `g1/weekly-cycle/1` |

Lesson and step IDs carry teacher data (notes, bookmarks, completion, resume), so they never change.

## 3. Links and provenance

A link is `{to: "<kind>:<id>", assertion, review, rule?, source?}`; kinds are `lesson`, `unit`,
`lo`, `objective`, `routine`, `material`, `assessment`, `section`, `resource`, `workbook`.
Every entity and link says where it came from:

- **stated**: printed in the source; `source` cites `{doc, pdf, printed, rect?}`.
- **derived**: follows from stated facts by a named `rule` (below). Reviewed derived links are
  allowed only if the owner decides plan §9.2 that way; until then they are shown as unreviewed.
- **editorial**: written by the project (summaries, short titles). Never shown as source text.

`review` is `unreviewed`, `source-compared` (checked against the page image by the project) or
`reviewed` (approved by someone with curriculum authority). The app shows only `reviewed`
editorial text (plan §4a).

### Derivation rules

| Rule | Meaning | Used for |
|---|---|---|
| `step-title-matches-routine` | step title equals a routine's name or a listed alias from the activity guide | Hindi step → routine |
| `v1-phase-id-to-routine` | Math GRR phase ids map to the plan types in the weekly overview | Math step → routine |
| `every-lesson-weekly-cycle` | every lesson links to its grade's weekly-cycle section | guide links |
| `objective-matches-lesson-title` | Math lesson title equals a weekly objective of its week | lesson → objective |
| `workbook-part2-by-week-day` (proposed) | Hindi workbook part 2 page tagged “सप्ताह w दिवस d–d” links to period-3 steps of those days | fills the v1 gap found in Phase 1 |

## 4. How both programs fit one model

The model fixes the backbone (program → outcomes → units → lessons → periods → steps → routine)
and lets each program fill only what its guide states:

| Concept | Hindi | Math |
|---|---|---|
| Outcomes | coded in workbooks for all grades; G3 guide coded; G1/G2 guides uncoded (both kept, open question) | 14 coded NIPUN LOs per grade, with sub-codes |
| Weekly objectives | none; units carry objectives as text | yes, 3 per week, each linked to a code (stated) |
| Periods | three 40-minute कालांश with stated roles; day 6 combines 2 and 3 (`number: [2, 3]`) | three periods; phases tagged by कालांश |
| Steps | numbered 1.1, 2.1 … with minute ranges (“5–7”) | GRR phases with whole minutes |
| Routine library | rich: what / why / how / watch-outs per activity | plan types and processes (ELPS, GRR, games, procedural fluency) |
| Day purpose | days 1–4 new, 5 revision, 6 assessment (stated, TG p16) | per the weekly overview; rule to be confirmed |
| Remediation | groups A/B by 50 % rule; staged plan | remedial plan after games, period 3 |

Fields a program does not state stay absent; nothing is filled in to make the two look alike.

## 5. Worked examples

**Hindi, `g1-hindi-w09-d02`** ([lesson](content-model/examples/hindi/lesson-g1-hindi-w09-d02.json)):
unit `g1-u-w09-12` (stated, annual objectives p15); day purpose `new-skills` (stated, p16); three
periods with labels and roles; steps 1.1–1.3 typed as `hi-picture-chart` and 3.1 as `hi-big-book`
by `step-title-matches-routine`; 3.2 as `hi-remedial-group-a`. Steps 2.1 “गतिविधियों की
संकल्पना पर कार्य” and 2.2 “कार्यपुस्तिका पर कार्य” match no routine name: they stay unlinked
and go to the review list (Phase 4 decides whether they are routines of their own). Step 2.2
links to workbook page 8 (stated). The [guide section](content-model/examples/hindi/guide-g1.json)
`g1/weekly-cycle` shows the decoded source text with an unreviewed editorial summary.

**Math, `g1-math-w09-d01`** ([lesson](content-model/examples/math/lesson-g1-math-w09-d01.json)):
LO `M101.1` (stated on the lesson page), objective `g1-w09-o1` (derived by title), unit
`g1-u-w09-11` (unit opener p17), conversation and GRR phases typed by `v1-phase-id-to-routine`,
practice linked to workbook page 9.

Both examples are generated from the published v1 records; the test checks that ids, titles
and actions are unchanged.

## 6. Open points for the review gate

1. Authoritative Hindi G1/G2 outcome list (workbook codes or guide numbering), and LO linking
   policy for derived links (plan §9.2).
2. Math day purposes: confirm which days are instruction, consolidation and remedial.
3. Whether Hindi steps such as “कार्यपुस्तिका पर कार्य” become routines (`practice` type).
4. Strand assignment for Math codes (the guides do not name strands; current values are the
   project's proposal, noted as unreviewed in each outcome's provenance note).
